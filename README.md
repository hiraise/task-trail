# TaskTrail

Открытый self-hosted трекер задач для небольших команд: проекты, участники с ролями, задачи,
комментарии, канбан-доски и поиск, без многодневной настройки.

Проект в разработке, этап 1: сервер по контракту API готов и работает на локальном стенде,
веб-клиент переходит на него.

## Структура

| Путь | Что там |
| --- | --- |
| `api/openapi.yaml` | Контракт API (OpenAPI 3.1) — источник истины для сервера и веба; сервер встраивает его для Swagger (`api/openapi.go`) |
| `server/` | API на Go (Gin, PostgreSQL); история перенесена из `hiraise/tt-backend` |
| `web/` | Веб-клиент на React и TypeScript (Vite); история перенесена из `hiraise/tt-frontend` |
| `docs/adr/` | Архитектурные решения — [индекс](docs/adr/README.md) |
| `stand/` | Локальный стенд в Docker: compose-файл и настройки nginx |
| `scripts/dev.sh` | Проверки и управление стендом |
| `CLAUDE.md` | Правила работы для AI-агентов |

## Разработка

Нужны Go (версия — в `server/go.mod`), Node.js (версия — `engines` в `web/package.json`) и Docker.

```bash
scripts/dev.sh check    # всё, что проверяет CI: правила, сервер, веб
scripts/dev.sh server   # только сервер: vet, тесты, golangci-lint
scripts/dev.sh web      # только веб: типы API из контракта, линтер, тесты, типы и сборка
```

Переменные окружения сервера — в [server/README.md](server/README.md), веба — в [web/README.md](web/README.md).

В VS Code те же команды — в Terminal → Run Task: стенд, проверка, правила проекта
([.vscode/tasks.json](.vscode/tasks.json)).

Каждая задача — своя ветка и, если сессий несколько, свой `git worktree` рядом с репозиторием.
`scripts/dev.sh cleanup` убирает worktree и ветки, чьи PR уже слиты. Обновления зависимостей
раз в неделю предлагает Dependabot ([ADR-0021](docs/adr/0021-dependabot-updates.md)).

## Локальный стенд

```bash
scripts/dev.sh up       # собрать, запустить и настроить пустую базу; на macOS сам запускает Docker Desktop
scripts/dev.sh smoke    # дымовая проверка: вход, приглашение по письму, задача, аватарка
scripts/dev.sh logs     # логи всех сервисов, или одного: logs server
scripts/dev.sh down     # остановить, база и файлы сохраняются
scripts/dev.sh reset    # остановить и стереть базу и файлы
```

| Адрес | Что там |
| --- | --- |
| http://localhost:3000 | веб-клиент; API — тот же адрес, путь `/api` |
| http://localhost:3025 | перехватчик почты Mailpit: письма приглашений и сброса пароля |
| http://localhost:3000/api/docs/ | Swagger сервера — после входа администратором в веб, в том же браузере |

Вход — `admin@tasktrail.local`, пароль `tasktrail`. Это первый аккаунт, администратор сервиса:
на пустой базе `up` создаёт его с адресом сервиса `http://localhost:3000` и подключает почту
к Mailpit через API администратора, как это сделал бы администратор в интерфейсе
([ADR-0015](docs/adr/0015-settings-in-admin-ui.md)). После этого регистрация закрыта: новых
пользователей зовут в проект, ссылка приглашения приходит в Mailpit. Что поменяли в настройках
на стенде, `up` не трогает; вернуть всё как было — `reset` и `up`.

Открывайте в Chrome или Firefox: сервер ставит cookie с флагом `Secure`, а Safari не принимает
их по `http`.

Стенд один на машину: `up` из любого worktree пересобирает его из своих `server/` и `web/`,
а `reset` стирает общую базу. С переходом на сервер из `server/` база стенда лежит в новом томе
`tasktrail_database` и начинается пустой: схема старого API новому серверу не подходит. Прежние
тома больше не нужны: `docker volume rm tasktrail_postgres tasktrail_pgdata`.

Сервер на стенде реализует весь контракт `api/openapi.yaml`, а веб переходит на него по частям
в шаге 6 этапа 1 ([план](docs/roadmap.md)). По контракту уже работают вход и выход, регистрация
первого аккаунта на пустой базе, принятие приглашения по ссылке из письма, восстановление
и сброс пароля, профиль: имя, аватарка, смена пароля. Ещё работают список проектов и «Мои задачи»
на телефоне. Не работает:

- страница проекта, участники, задачи проекта и сама задача: веб ждёт права `permissions`, а сервер
  отдаёт роль `role`;
- создание проекта и добавление участников: поля запроса называются иначе, а лишние поля сервер
  отвергает;
- создание и изменение задачи, смена статуса и исполнителя: другие адреса и поля;
- раздел администратора — экранов ещё нет;
- доски, комментарии и поиск — заглушки, сервер их не отдаёт.

То, чего не показывает веб, проверяется в Swagger.

## Интеграции

Внешние сервисы подключаются по желанию: без них TaskTrail работает.

### Почта

Сервер шлёт письма со ссылками: сброс пароля, приглашение в проект тому, у кого ещё нет аккаунта,
и извещение тому, кого добавили в проект сразу.

Письмо уходит только на SMTP-сервер, который подключил администратор сервиса, и только в момент
запроса, которому оно нужно, например «Забыли пароль?» или приглашение в проект: адрес получателя,
тема и текст — имя пригласившего, название проекта, ссылка на веб. Токен в ссылке сброса
одноразовый, в базе хранятся только хеши токенов. Пароль SMTP лежит в базе
зашифрованным ключом из `APP_SECRET` и уходит только на сервер и порт, для которых его ввели.

Включает почту администратор: сохраняет сервер SMTP, порт, шифрование (нет, STARTTLS или TLS),
отправителя и, если нужно, логин и пароль; там же меняет и отключает. Перед сохранением сервер
подключается к SMTP с этими настройками, входит и спрашивает, примет ли SMTP письмо от этого
отправителя, — само письмо не уходит; не вышло — настройки не сохраняются. Проверить доставку
администратор может тестовым письмом себе. Сервер это уже умеет (`/v1/admin/settings/mail`),
экраны раздела администратора в вебе — в шаге 6.4 этапа 1 ([план](docs/roadmap.md)).

Без почты «Забыли пароль?» отвечает, что почта не подключена: ссылку сброса выдаёт администратор,
а тому, кто управляет сервером, — команда `password-reset-link` ([server/README.md](server/README.md)).
Ссылку приглашения без почты пригласивший получает в ответе и передаёт сам. Почему так —
[ADR-0017](docs/adr/0017-mail-in-admin-ui.md).

## План

Подробно, со следующим шагом и открытыми вопросами, — [docs/roadmap.md](docs/roadmap.md).

1. **Этап 0 — закрыт.** Единый репозиторий, правила и ADR, проверки и CI, локальный стенд.
2. **Этап 1.** Контракт API в `api/openapi.yaml` и сервер, который его реализует, — веб переходит на него.
3. **Этап 2.** Комментарии, доски, поиск, архив, ключи задач — ядро из [ADR-0004](docs/adr/0004-lightweight-tracker-scope.md).
4. **Этап 3.** Приоритет, срок, метки, уведомления и остальное «после ядра».
5. **Этап 4.** Android-клиент.
