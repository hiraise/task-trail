# TaskTrail

Открытый self-hosted трекер задач для небольших команд: проекты, участники с ролями, задачи,
комментарии, канбан-доски и поиск, без многодневной настройки.

Проект в разработке: фундамент готов (единый репозиторий, правила работы, проверки, локальный
стенд), дальше — этап 1, сервер под контракт веб-клиента.

## Структура

| Путь | Что там |
| --- | --- |
| `server/` | API на Go (Gin, PostgreSQL); история перенесена из `hiraise/tt-backend` |
| `web/` | Веб-клиент на React и TypeScript (Vite); история перенесена из `hiraise/tt-frontend` |
| `docs/adr/` | Архитектурные решения — [индекс](docs/adr/README.md) |
| `stand/` | Локальный стенд в Docker: compose-файл и настройки nginx |
| `scripts/dev.sh` | Проверки и управление стендом |
| `CLAUDE.md` | Правила работы для AI-агентов |

## Разработка

Нужны Go (версия — в `server/go.mod`), Node.js 22 и Docker.

```bash
scripts/dev.sh check    # всё, что проверяет CI: правила, сервер, веб
scripts/dev.sh server   # только сервер: vet, тесты, golangci-lint
scripts/dev.sh web      # только веб: линтер, тесты, типы и сборка
```

Переменные окружения сервера — в [server/README.md](server/README.md), веба — в [web/README.md](web/README.md).

## Локальный стенд

```bash
scripts/dev.sh up       # собрать и запустить; на macOS сам запускает Docker Desktop
scripts/dev.sh smoke    # дымовая проверка: вход через письмо, обновление токена, проект
scripts/dev.sh logs     # логи всех сервисов, или одного: logs server
scripts/dev.sh down     # остановить, база сохраняется
scripts/dev.sh reset    # остановить и стереть базу
```

| Адрес | Что там |
| --- | --- |
| http://localhost:3000 | веб-клиент; API — тот же адрес, путь `/api` |
| http://localhost:8025 | перехватчик почты Mailpit: письма подтверждения и сброса пароля |
| http://localhost:3000/api/docs/index.html | Swagger сервера, логин и пароль — `root` |

Открывайте в Chrome или Firefox: сервер ставит cookie с флагом `Secure`, а Safari не принимает
их по `http`. Чтобы войти, зарегистрируйтесь и откройте ссылку из письма в Mailpit.

Стенд один на машину: `up` из любого worktree пересобирает его из своего `web/`, а `reset`
стирает общую базу.

Пока на стенде работает эталон старого API ([ADR-0010](docs/adr/0010-local-development.md)) —
сервер из истории, с контрактом которого писался веб-клиент. Этап 1 заменит его сервером
из `server/`. Контракты уже разошлись, поэтому в вебе на эталоне не работает:

- создание задачи: клиент передаёт ID проекта строкой, а старый API ждёт число;
- добавление участников: клиент шлёт список адресов, а старый API ждёт объект `{"emails": […]}`;
- смена статуса и исполнителя: старый API отвечает пустым телом, а клиент ждёт задачу —
  статус меняется, но веб показывает ошибку;
- загрузка аватарки: старый API хранит файлы в S3, а на стенде его нет;
- доски, комментарии и поиск — заглушки, сервер их не отдаёт.

## План

Подробно, со следующим шагом и открытыми вопросами, — [docs/roadmap.md](docs/roadmap.md).

1. **Этап 0 — закрыт.** Единый репозиторий, правила и ADR, проверки и CI, локальный стенд.
2. **Этап 1.** Контракт API в `api/openapi.yaml` и сервер, который его реализует, — веб переходит на него.
3. **Этап 2.** Комментарии, доски, поиск, архив, ключи задач — ядро из [ADR-0004](docs/adr/0004-lightweight-tracker-scope.md).
4. **Этап 3.** Приоритет, срок, метки, уведомления и остальное «после ядра».
5. **Этап 4.** Android-клиент.
