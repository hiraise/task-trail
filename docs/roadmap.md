# План работ

Для агентов: где проект сейчас, что делать дальше и в каком порядке. Решения — в ADR, правила —
в [CLAUDE.md](../CLAUDE.md), здесь — очередь работ. Закрыл шаг — обнови этот файл в том же PR.

## Где мы сейчас

Этап 0 закрыт 2026-10-21: единый репозиторий (история `hiraise/tt-backend` и `hiraise/tt-frontend`
перенесена в `server/` и `web/`, старые репозитории архивированы), правила и ADR 0001–0010,
проверки `scripts/dev.sh check` и CI, локальный стенд `scripts/dev.sh up`.

- `server/` умеет только доступ — `/v1/access/*`: регистрация с подтверждением почты, вход,
  обновление токенов, выход, сброс и смена пароля. Схема БД `server/migrations/000001_init.*`
  уже по [ADR-0003](adr/0003-fixed-roles-and-statuses.md) — UUID, роль и статус строками —
  и содержит таблицы проектов, участников и задач.
- `web/` — экраны по дизайну: вход, проекты, участники, задачи, профиль; доски, комментарии
  и поиск — заглушки. Веб ходит в старый контракт `/v1/auth/*`: адреса —
  `web/src/infrastructure/config/apiRoutes.ts`.
- На стенде пока работает эталон старого API (`LEGACY_API_COMMIT` в `scripts/dev.sh`): с ним
  писался веб. Что на нём не работает — [README](../README.md), «Локальный стенд».

## Этап 1 — контракт API и сервер, на который переходит веб

Цель: на стенде работает сервер из `server/`, веб полностью работает с ним, эталон старого API удалён.

1. **Контракт.** Опиши `api/openapi.yaml` (OpenAPI 3.1) от того, что ждёт веб: адреса —
   `apiRoutes.ts`, тела запросов — `web/src/application/payloads/`, ответы — zod-схемы
   `web/src/domain/models/`. Поведение сверяй с эталоном: `git show 71b514e:server/docs/swagger.yaml`
   и обработчики `git show 71b514e:server/internal/controller/http/v1/<файл>.go`. Расхождения веба
   и эталона, которые контракт должен решить: ID — строки UUID (ADR-0003), тело добавления
   участников, ответ смены статуса и исполнителя, `avatarUrl: null`. Отступление от поведения
   эталона — ADR. Доступ описывай уже по ADR-0011 и ADR-0012: регистрация первого аккаунта,
   приглашения со ссылками в ответе, когда почта выключена, настройки для веба, без `verify`
   и `resend-verification`; файлы — по ADR-0013.
2. **Проверка контракта.** Типы веба генерируются из контракта, ответы сервера проверяются по нему
   тестами, всё — в `scripts/dev.sh check` ([ADR-0005](adr/0005-monorepo-api-contract.md),
   [ADR-0009](adr/0009-checks-and-ci.md)). Генератор типов и валидатор OpenAPI — новые
   зависимости, каждая через ADR.
3. **Доступ.**
   - Верни пути `/v1/access/*` к `/v1/auth/*` из контракта.
   - Перестрой доступ по ADR-0011: первый аккаунт, приглашения (таблица `invitations` —
     новая миграция), почта в нижнем регистре, хеши токенов, удаление подтверждения почты.
   - Сделай почту необязательной по ADR-0012: `SMTP_*` и лишние `FRONTEND_*_URL`, команда
     сервера для сброса пароля. Обнови таблицу переменных в `server/README.md` и сними оговорку
     про SMTP в принципе 2 [CLAUDE.md](../CLAUDE.md).
   - Доделай TODO: при повторном использовании refresh-токена отзывай все токены пользователя
     (`logout.go`, `refresh.go`). Делай это отдельной транзакцией, иначе отзыв откатится вместе
     с ошибкой.
   - Доделай TODO: периодическая очистка токенов (`internal/app/app.go`).
   - Убери нарушение [ADR-0007](adr/0007-server-architecture.md):
     `internal/domain/service/access_token.go` импортирует `application/dto`. Затем добавь проверку
     импортов в `scripts/rules.mjs`.
4. **Модули сервера** по ADR-0007, в порядке зависимостей веба:
   - пользователь: `/v1/users/me`, кандидаты в проект, аватарка — файлы по ADR-0013;
   - проекты и участники с ролями (ADR-0003). Если веб остаётся на пермишенах, отдавай набор
     пермишенов по роли: `web/src/shared/utils/userRole.ts` и так сводит их к ролям;
   - статусы: фиксированные, с постоянными ID;
   - задачи ([ADR-0002](adr/0002-task-edit-endpoints.md)).

   Репозитории покрывай интеграционными тестами на PostgreSQL; в CI для них нужен сервис PostgreSQL.
5. **Стенд на новый сервер.**
   - В `stand/compose.yaml` сервер собирается из `server/`.
   - Убери `LEGACY_API_COMMIT`, одинаковые секреты токенов и `S3_ENABLED`.
   - Том для `FILES_DIR` и `client_max_body_size` в `stand/nginx.conf.template` (ADR-0013).
   - Дополни `scripts/dev.sh smoke` приглашением и задачами.
   - Обнови README, раздел «Локальный стенд», и [ADR-0010](adr/0010-local-development.md).
6. **Веб.** Приведи слой данных к контракту: `infrastructure/repositories`, `domain/models`.
   Экраны, которые трогаешь, сливай из пар Mobile/Desktop ([ADR-0008](adr/0008-web-architecture.md)).
   Доступ — по ADR-0011 и ADR-0012: регистрация только для первого аккаунта, экран принятия
   приглашения, ссылки приглашений для копирования, когда почта выключена; экран подтверждения
   почты удали.
   Экрана приглашения в Figma нет — собери его из компонентов экрана регистрации.

Доступ и файлы на этапе 1 строятся по решениям заказчика:
[ADR-0011](adr/0011-invite-only-signup.md) — новые пользователи приходят по приглашению,
[ADR-0012](adr/0012-optional-mail.md) — почта по желанию,
[ADR-0013](adr/0013-files-on-server-disk.md) — файлы на диске сервера.

## Что держать в голове

- `main` защищён: только PR с зелёной «Проверкой», и ветка должна быть свежей относительно
  `main` — перед слиянием `gh pr update-branch <N>`.
- Однажды GitHub не запустил CI на огромный PR. Если проверок нет через пару минут,
  закрой и открой PR заново: `gh pr close <N> && gh pr reopen <N>`.
- Стенд один на машину. Проверяй его в Chrome или Firefox: Safari не принимает Secure-cookies по http.
- В вебе 12 старых предупреждений ESLint — убирай, когда трогаешь эти файлы.
