## Где мы сейчас

Этап 0 закрыт 2026-10-21: единый репозиторий (история `hiraise/tt-backend` и `hiraise/tt-frontend`
перенесена в `server/` и `web/`, старые репозитории архивированы), правила и ADR 0001–0010,
проверки `scripts/dev.sh check` и CI, локальный стенд `scripts/dev.sh up`.

  обновление токенов, выход, сброс и смена пароля. Схема БД `server/migrations/000001_init.*`
  уже по [ADR-0003](adr/0003-fixed-roles-and-statuses.md) — UUID, роль и статус строками —
  и содержит таблицы проектов, участников и задач.
- `web/` — экраны по дизайну: вход, проекты, участники, задачи, профиль; доски, комментарии
  и поиск — заглушки. Веб ходит в старый контракт `/v1/auth/*`: адреса —
  `web/src/infrastructure/config/apiRoutes.ts`.
- Контракт `api/openapi.yaml` описан (шаг 1 этапа 1), соглашения — [ADR-0018](adr/0018-api-conventions.md).
  Сервер и веб ему пока не соответствуют.
- На стенде пока работает эталон старого API (`LEGACY_API_COMMIT` в `scripts/dev.sh`): с ним
  писался веб. Что на нём не работает — [README](../README.md), «Локальный стенд».

## Этап 1 — контракт API и сервер, на который переходит веб

Цель: на стенде работает сервер из `server/`, веб полностью работает с ним, эталон старого API удалён.

1. ~~**Контракт.**~~ Готово: `api/openapi.yaml` по соглашениям [ADR-0018](adr/0018-api-conventions.md).
   Меняя API дальше, меняй контракт в том же PR (ADR-0005). Эталон старого API для сверки
   поведения — `git show 71b514e:server/docs/swagger.yaml` и обработчики
   `git show 71b514e:server/internal/controller/http/v1/<файл>.go`.
2. **Проверка контракта.** Типы веба генерируются из контракта, ответы сервера проверяются по нему
   тестами, всё — в `scripts/dev.sh check` ([ADR-0005](adr/0005-monorepo-api-contract.md),
   [ADR-0009](adr/0009-checks-and-ci.md)). Генератор типов и валидатор OpenAPI — новые
   зависимости, каждая через ADR. Пока проверки нет, проверяй контракт вручную:
   `npx --yes @redocly/cli@1 lint api/openapi.yaml`.
3. **Доступ.**
   - Приведи эндпоинты доступа к контракту: пути `/v1/auth/*`, ответы и коды ошибок по ADR-0018.
     `middleware/error.go` отдаёт `{ code, message, details }` и на непредвиденную ошибку тоже,
     ключи `details` — имена полей из JSON (`newPassword`), а не `strings.ToLower` от имени в Go.
   - Исправь выход: cookie `rt` ставится с путём только обновления сессии, поэтому `logout` её
     не получает и всегда отвечает 401. По контракту путь cookie — `/v1/auth/`. Вход, обновление
     и выход заодно удаляют `rt` со старым путём `/v1/auth/refresh`: старая cookie с более точным
     путём иначе уходит первой и заслоняет новую.
   - Пароль: не длиннее 72 байт в UTF-8 (предел bcrypt), длиннее — 422, а не 500.
   - Swagger показывает `api/openapi.yaml` вместо сгенерированного `server/docs/` (ADR-0005),
     `make swag` и аннотации `@Summary` удали.
   - Сократи окружение по ADR-0015: `APP_SECRET` вместо секретов токенов, константы вместо
     времени жизни и имён, встроенные миграции, таблица настроек с шифрованием секретов.
     Обнови таблицу переменных в `server/README.md`. Миграции станут обязательными, поэтому
     сначала исправь `server/internal/pkg/postgres/migrate.go`: он дописывает `?sslmode=disable`
     к адресу базы и ломает адрес, в котором уже есть параметры.
   - Перестрой доступ по ADR-0016: первый аккаунт — администратор (ADR-0014), приглашения
     (таблица `invitations` — новая миграция), почта в нижнем регистре, хеши токенов, удаление
     подтверждения почты.
   - Почта по ADR-0017: настройки SMTP из базы вместо `SMTP_*` и `FRONTEND_*`, команда сервера
     для сброса пароля. Сними оговорку про SMTP в принципе 2 [CLAUDE.md](../CLAUDE.md).
   - Доделай TODO: при повторном использовании refresh-токена отзывай все токены пользователя
     (`logout.go`, `refresh.go`). Делай это отдельной транзакцией, иначе отзыв откатится вместе
     с ошибкой. Повтор в течение 30 секунд после обновления — другая вкладка, а не кража:
     выдай новую пару (контракт, `refreshSession`).
   - Доделай TODO: периодическая очистка токенов (`internal/app/app.go`).
   - Убери нарушение [ADR-0007](adr/0007-server-architecture.md):
     `internal/domain/service/access_token.go` импортирует `application/dto`. Затем добавь проверку
     импортов в `scripts/rules.mjs`.
4. **Модули сервера** по ADR-0007, в порядке зависимостей веба:
   - пользователь: `/v1/users/me`, кандидаты в проект, аватарка — файлы по ADR-0013;
   - проекты и участники с ролями (ADR-0003): API отдаёт `role`, а не набор прав (ADR-0018);
   - статусы: фиксированные, с постоянными ID;
   - задачи ([ADR-0002](adr/0002-task-edit-endpoints.md));
   - администрирование (ADR-0014, ADR-0015): настройки сервиса, почта с проверкой подключения,
     пользователи — назначение администратора и ссылка сброса пароля.

   Репозитории покрывай интеграционными тестами на PostgreSQL; в CI для них нужен сервис PostgreSQL.
5. **Стенд на новый сервер.**
   - В `stand/compose.yaml` сервер собирается из `server/`.
   - Убери `LEGACY_API_COMMIT`, одинаковые секреты токенов и `S3_ENABLED`.
   - Том для `FILES_DIR` и `client_max_body_size` в `stand/nginx.conf.template` (ADR-0013).
   - `scripts/dev.sh up` создаёт первый аккаунт с адресом `http://localhost:3000` и сохраняет
     настройки Mailpit через API администратора (ADR-0015, ADR-0017); переменных `SMTP_*`
     и `FRONTEND_*` у сервера нет, сертификаты Mailpit и `SSL_CERT_FILE` убери.
   - Дополни `scripts/dev.sh smoke` приглашением и задачами.
   - Обнови README, раздел «Локальный стенд», и [ADR-0010](adr/0010-local-development.md).
6. **Веб.** Приведи слой данных к контракту: `infrastructure/repositories`, `domain/models`.
   Экраны, которые трогаешь, сливай из пар Mobile/Desktop ([ADR-0008](adr/0008-web-architecture.md)).
   Доступ — по ADR-0016 и ADR-0017: регистрация только для первого аккаунта, экран принятия
   приглашения, ссылки приглашений для копирования, когда почта выключена; экран подтверждения
   почты удали. Экрана приглашения в Figma нет — собери его из компонентов экрана регистрации.
   Тайм-аут запросов с письмами (участники, создание проекта, настройки почты) — не меньше
   20 секунд, сейчас у всех запросов 5 (`web/src/infrastructure/http/axiosClient.ts`).
   Права в интерфейсе — по роли: `web/src/shared/utils/userRole.ts` перепиши с `permissions` на `role`.
   Раздел администратора (ADR-0014): настройки сервиса, почта, пользователи. Его в Figma тоже
   нет — сначала нарисуй экраны на дизайн-системе Figma и согласуй с заказчиком.

Доступ, настройки и файлы на этапе 1 строятся по решениям заказчика:
