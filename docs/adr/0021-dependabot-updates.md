# ADR-0021: Обновления зависимостей и действий GitHub предлагает Dependabot

- **Статус:** Предложено
- **Дата:** 2026-10-21
- **Затрагивает:** `.github/dependabot.yml`, `server/go.mod`, `web/package.json`, `.github/workflows/`

## Контекст

Зависимости поднимаются вручную, когда до них доходят руки. Действия GitHub закреплены по SHA
([ADR-0009](0009-checks-and-ci.md)) и без подсказки не обновятся никогда — даже с исправлениями
уязвимостей.

## Решение

- Обновления предлагает Dependabot по `.github/dependabot.yml`: Go-модули `server/` и npm-пакеты
  `web/` — раз в неделю, действия GitHub — раз в месяц.
- Минорные и патч-обновления одной экосистемы приходят одним PR (группы `server`, `web`, `actions`).
  Мажорные — отдельными PR: они могут требовать правок кода.
- `@hey-api/openapi-ts` — всегда отдельным PR: новая версия генератора меняет типы, и их
  перегенерирует агент в ветке этого PR ([ADR-0020](0020-web-api-types.md)).
- PR Dependabot проходит тот же CI. Сливает его заказчик при зелёном CI; упал CI — агент чинит
  в ветке этого PR по просьбе заказчика.
- Обновление без смены поведения ADR не требует ([ADR-0006](0006-tech-stack.md)). Новую
  библиотеку Dependabot не добавляет, поэтому ADR о стеке он не обходит.

## Последствия

- Версию golangci-lint в `scripts/dev.sh` и образы стенда в `stand/compose.yaml` Dependabot
  не видит — их поднимают вручную.
- Коммиты и PR Dependabot — на английском: правило о русском языке коммитов — для агентов.

## Альтернативы

- Renovate — гибче, но это отдельное приложение GitHub; для трёх экосистем хватает встроенного Dependabot.
