# ADR-0018: Соглашения контракта API: UUID, ошибка с кодом, изменение возвращает ресурс

- **Статус:** Принято
- **Дата:** 2026-10-21
- **Затрагивает:** `api/openapi.yaml`, HTTP-слой `server/internal/presentation/`, `server/internal/presentation/http/middleware/error.go`, клиент API `web/src/infrastructure/`

## Контекст

Контракт `api/openapi.yaml` ([ADR-0005](0005-monorepo-api-contract.md)) пишется заново, и эталон
старого API в нём не годится как образец: числовые ID, ошибка без кода, после изменения — только `id`.
Без общих правил каждый новый эндпоинт решал бы это по-своему.

## Решение

- Пути — `/v1/...`, ресурсы во множественном числе, `kebab-case`; поля JSON — `camelCase`.
- ID — строки UUID; время — строки ISO 8601 в UTC. Пустое значение — `null`: поле в ответе есть всегда.
- Данные запроса — в теле JSON; в пути — только ID ресурса. Токены из ссылок (приглашение, сброс
  пароля) — только в теле, чтобы они не оседали в логах прокси.
- Создание отвечает `201` и созданным ресурсом, изменение — `200` и изменённым ресурсом, удаление
  и действие без результата — `204` без тела.
- Ошибка — `{ code, message, details }`. `code` — значение из `ErrorCode` в контракте, по нему
  клиент выбирает реакцию; `message` — для логов, не для показа; `details` — поля с ошибками
  проверки или `null`.
- Статусы ошибок: `401` — нет входа, `403` — не хватает роли, `404` — нет ресурса или пользователь
  не участник его проекта (существование не выдаём), `409` — конфликт с состоянием, `422` —
  проверка данных, `502` — не ответила внешняя служба, например почта.
- Доступ к проекту — по роли `owner`, `admin` или `member` ([ADR-0003](0003-fixed-roles-and-statuses.md)):
  API отдаёт роль, а не набор прав. Нужную роль контракт называет у каждого эндпоинта.
- Список отдаётся массивом без обёртки и без постраничности, пока она не нужна.

## Последствия

- Веб на этапе 1 переходит на эти правила: ID-строки, `role` вместо `permissions`, полная задача
  в ответе на смену статуса и исполнителя, `avatarId` вместо `avatarUrl`, статусы задач — общий
  список `GET /v1/task-statuses`.
